## Task & Workflow Routing

| Task | Route / Required Procedure |
| --- | --- |
| Writing or reviewing code | Read `docs/code-standards.md`, `LESSONS.md`, and the target `docs/subsystems/*.md` first. |
| Running tests, fixtures, or packaged QA | Read `docs/testing.md` and `docs/subsystems/ci-release-qa.md`. Wrap ad-hoc Node/npm commands with `npm run ci:run -- ...`; run `npm run ci:local` for full Mac + `ssh win` (Windows NSIS + Android Emulator + WSL2 Ubuntu Linux tests & `.deb`/`.rpm`/`.zip`) verification and `ci/local-distributed` status writeback (`npm run ci:local -- --publish` if pushed or squash-merged after running). |
| Bug fixes & features | 1. Open a GitHub Issue on `Lycidas97/claude-desktop-bridge` (`gh issue create --repo Lycidas97/claude-desktop-bridge`).<br>2. Work in an isolated `git worktree` branch. Before review run only `npm run typecheck` and the tests related to the changed files (`npm run ci:run -- exec -w <workspace> -- vitest related --run <files>`; add `npm run test:browser` when client UI changed); full suites run once, inside `npm run ci:local` after review converges (see `docs/parallel-workflow.md` **CI**). Scale checks to risk per `docs/code-standards.md` §5. Parallel forked worktrees treat `LESSONS.md`, `docs/subsystems/*.md`, and shared `memory/` as **read-only** (single-writer ownership: surface `0–2` verified candidate lessons in the completion report instead of editing concurrently).<br>3. Push branch to `origin` (`Lycidas97/claude-desktop-bridge`) and open a PR referencing `Fixes #N` using `.github/pull_request_template.md`, then try `mcp__ccd_pr__set_monitor` with `url`, `auto_fix: true`, `address_comments: true`; if the host refuses, do not work around it (fixes are relayed by `SendMessage`).<br>4. Review, verify, and merge per **PR review & merge**, then sync `main` and, unless the PR was docs-only, publish the tree receipt (`npm run ci:local -- --publish`) when the squash commit's tree matches the verified head; otherwise skip it (the release commit is verified per `docs/RELEASE.md`).<br>For several Issues at once, follow `docs/parallel-workflow.md`. |
| PR review & merge | Follow `docs/parallel-workflow.md` (roles, review tiers, messages, briefs, models). Hard rules: the implementing fork never reviews or merges its own PR; reviewers get only the PR number and SHA; merge only the reviewed SHA with `ci/local-distributed` verified green via `gh api` (docs-only PRs skip `ci:local` and list `ci:local — docs only` under `## Not Run`), using `gh pr merge <pr-number> --repo Lycidas97/claude-desktop-bridge --squash --match-head-commit <reviewed-sha>`. |
| Offline consolidation (Dreaming) & pre-release retro | Audit recent `main` commits **and** recent session transcripts against `LESSONS.md` (both pitfalls and verified recipes; unverified hypotheses are barred). Verify that paths, selectors, and links in `LESSONS.md` and `docs/subsystems/*.md` still match `main` and prune stale entries or hand-copied file lists. When an entry reaches `Seen 3×` across **3 distinct calendar dates**, promote subsystem-scoped rules into the owning `docs/subsystems/*.md` (`Critical Invariants`) and cross-cutting rules into `docs/code-standards.md`, then delete it from `LESSONS.md`. |
| Dogfood build & runtime incidents (OOM, freeze, leak) | Read `docs/dogfood.md`. This Mac always runs a build of current `main` (`npm run ci:run -- exec -- node scripts/dogfood-install.mjs`); most bugs are expected to surface in use. Runtime incidents follow its reproduce-first procedure: no static multi-model investigation before a diagnostic patch has been tried, and no fix ships for an unreproduced incident. |
| Cutting a release | Read `docs/RELEASE.md`. The target commit on `main` **must** be an ancestor of `origin/main` with `ci/local-distributed == "success"` (via `npm run ci:local` or `--publish` on an identical `HEAD^{tree}` squash commit) or a `completed` + `success` manual `CI` workflow run; cancelled or incomplete runs never qualify. It must also have run as the dogfood build through several hours of real phone use with no open regression (`docs/dogfood.md`). |
| Architecture & protocol overview | Read `docs/ARCHITECTURE.md` and `docs/SECURITY.md`. |
