## Task & Workflow Routing

| Task | Route / Required Procedure |
| --- | --- |
| Writing or reviewing code | Read `docs/code-standards.md`, `LESSONS.md`, and the target `docs/subsystems/*.md` first. |
| Running tests, fixtures, or packaged QA | Read `docs/testing.md` and `docs/subsystems/ci-release-qa.md`. Wrap ad-hoc Node/npm commands with `npm run ci:run -- ...`; run `npm run ci:local` for full Mac + `ssh win` (Windows NSIS + Android Emulator + WSL2 Ubuntu Linux tests & `.deb`/`.rpm`/`.zip`) verification and `ci/local-distributed` status writeback (`npm run ci:local -- --publish` if pushed or squash-merged after running). |
| Bug fixes & features | 1. Open a GitHub Issue on `Lycidas97/claude-desktop-bridge` (`gh issue create --repo Lycidas97/claude-desktop-bridge`).<br>2. Work in an isolated `git worktree` branch and run `npm run ci:local` to verify across Mac + Windows + Android + WSL2 Linux (skip for docs-only diffs; see **PR review & merge** step 3). Parallel forked worktrees treat `LESSONS.md`, `docs/subsystems/*.md`, and shared `memory/` as **read-only** (single-writer ownership: surface `0–2` verified candidate lessons in the completion report instead of editing concurrently).<br>3. Push branch to `origin` (`Lycidas97/claude-desktop-bridge`), publish `ci/local-distributed` if deferred (`npm run ci:local -- --publish`), and open a PR referencing `Fixes #N` using `.github/pull_request_template.md`, then enable `ccd_pr` monitoring (`mcp__ccd_pr__set_monitor` with `url`, `auto_fix: true`, `address_comments: true`).<br>4. Review and merge per **PR review & merge**, then sync `main` and, unless the PR was docs-only, publish the tree receipt (`npm run ci:local -- --publish`). |
| PR review & merge | The Issue patrol (dispatching) session owns review and merge; the implementing fork never reviews or merges its own PR, and no standing review session exists.<br>1. After the fork reports, spawn a **fresh-context** reviewer (non-`fork` `Agent`) given only the Issue text, PR number + head SHA, and the routed `docs/subsystems/*.md`, `docs/code-standards.md`, and `LESSONS.md` — never the patrol's own analysis or the fork brief. It returns `[BLOCKER]`/`[NIT]` findings plus `0–2` verified candidate lessons.<br>2. The patrol posts the reviewer's findings verbatim as inline PR comments (`gh api repos/Lycidas97/claude-desktop-bridge/pulls/<pr-number>/comments -f commit_id=<reviewed-sha> -f path=<file> -F line=<line> -f side=RIGHT -f body=<finding>`; findings on lines outside the diff go in one `gh pr comment <pr-number> --repo Lycidas97/claude-desktop-bridge --body <findings>`). The fork fixes them in its own worktree via `ccd_pr` `address_comments` and re-runs `npm run ci:local` on each fix head unless the PR is docs-only. If the round had a `[BLOCKER]`, re-run step 1 on the new head SHA. After a NIT-only round, the patrol itself checks only the fix commits (`git diff <reviewed-sha>..<new-head-sha>`) and `<new-head-sha>` becomes the reviewed SHA. A round with no findings leaves the step 1 head SHA as the reviewed SHA.<br>3. Merge **only** after the CI gate passes on the reviewed SHA, then run `gh pr merge <pr-number> --repo Lycidas97/claude-desktop-bridge --squash --match-head-commit <reviewed-sha>`. The gate is green `ci/local-distributed`, except for **docs-only** PRs (every path in `gh pr diff <pr-number> --repo Lycidas97/claude-desktop-bridge --name-only` matches the `NON_DOC` exclusion regex in the `changes` job of `.github/workflows/ci.yml`), which skip `ci:local` and list `ci:local — docs only` under `## Not Run`. The patrol then consolidates the fork's and reviewer's candidate lessons (single writer).<br>Spin off a short-lived per-PR review session (runs steps 1–2 for that PR and returns the reviewed SHA plus candidate lessons to the patrol, which performs step 3) only when in-flight PRs block Issue dispatch. |
| Offline consolidation (Dreaming) & pre-release retro | Audit recent `main` commits **and** recent session transcripts against `LESSONS.md` (both pitfalls and verified recipes; unverified hypotheses are barred). Verify that paths, selectors, and links in `LESSONS.md` and `docs/subsystems/*.md` still match `main` and prune stale entries or hand-copied file lists. When an entry reaches `Seen 3×` across **3 distinct calendar dates**, promote subsystem-scoped rules into the owning `docs/subsystems/*.md` (`Critical Invariants`) and cross-cutting rules into `docs/code-standards.md`, then delete it from `LESSONS.md`. |
| Cutting a release | Read `docs/RELEASE.md`. The target commit on `main` **must** be an ancestor of `origin/main` with `ci/local-distributed == "success"` (via `npm run ci:local` or `--publish` on an identical `HEAD^{tree}` squash commit) or a `completed` + `success` manual `CI` workflow run; cancelled or incomplete runs never qualify. |
| Architecture & protocol overview | Read `docs/ARCHITECTURE.md` and `docs/SECURITY.md`. |
