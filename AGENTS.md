## Task & Workflow Routing

| Task | Route / Required Procedure |
| --- | --- |
| Writing or reviewing code | Read `docs/code-standards.md`, `LESSONS.md`, and the target `docs/subsystems/*.md` first. |
| Running tests, fixtures, or packaged QA | Read `docs/testing.md` and `docs/subsystems/ci-release-qa.md`. Wrap ad-hoc Node/npm commands with `npm run ci:run -- ...`; run `npm run ci:local` for full Mac + `ssh win` (Windows NSIS + Android Emulator + WSL2 Ubuntu Linux tests & `.deb`/`.rpm`/`.zip`) verification and `ci/local-distributed` status writeback (`npm run ci:local -- --publish` if pushed or squash-merged after running). |
| Bug fixes & features | 1. Open a GitHub Issue on `Lycidas97/claude-desktop-bridge` (`gh issue create --repo Lycidas97/claude-desktop-bridge`).<br>2. Work in an isolated `git worktree` branch and run the subsystem's minimum verification locally; `npm run ci:local` runs only after review converges (see **PR review & merge** step 3). Parallel forked worktrees treat `LESSONS.md`, `docs/subsystems/*.md`, and shared `memory/` as **read-only** (single-writer ownership: surface `0–2` verified candidate lessons in the completion report instead of editing concurrently).<br>3. Push branch to `origin` (`Lycidas97/claude-desktop-bridge`) and open a PR referencing `Fixes #N` using `.github/pull_request_template.md`, then try `mcp__ccd_pr__set_monitor` with `url`, `auto_fix: true`, `address_comments: true`; if the host refuses, do not work around it (fixes are relayed by `SendMessage`).<br>4. Review, verify, and merge per **PR review & merge**, then sync `main` and, unless the PR was docs-only, publish the tree receipt (`npm run ci:local -- --publish`) when the squash commit's tree matches the verified head; otherwise skip it (the release commit is verified per `docs/RELEASE.md`).<br>For several Issues at once, follow `docs/parallel-workflow.md`. |
| PR review & merge | The Issue patrol (dispatching) session owns review and merge; the implementing fork never reviews or merges its own PR. Full protocol, briefs, and the patrol checklist: `docs/parallel-workflow.md`.<br>1. A review session paired with the PR, started together with the fork, receives only the PR number + head SHA — never the patrol's analysis or the fork brief. It posts **one** PR review bound to that SHA (`gh api repos/Lycidas97/claude-desktop-bridge/pulls/<pr-number>/reviews` with `commit_id`, `[BLOCKER]`/`[NIT]` line comments, off-diff findings in the body) and `SendMessage`s the patrol its verdict plus `0–2` verified candidate lessons.<br>2. The patrol relays the review to the fork via `SendMessage`; the fork fixes in its own worktree and reports the new head SHA. If the round had a `[BLOCKER]`, the same reviewer re-reviews the new head. After a NIT-only round, the same reviewer checks only the fix commits (`git diff <reviewed-sha>..<new-head-sha>`) and, if clean, `<new-head-sha>` becomes the reviewed SHA. A round with no findings leaves the step 1 head SHA as the reviewed SHA.<br>3. After review converges, the fork runs `npm run ci:local` on the reviewed SHA (switched to `group/bridge-runner` for the run). Merge **only** with green `ci/local-distributed` on that SHA: `gh pr merge <pr-number> --repo Lycidas97/claude-desktop-bridge --squash --match-head-commit <reviewed-sha>`. **Docs-only** PRs (every path in `gh pr diff <pr-number> --repo Lycidas97/claude-desktop-bridge --name-only` matches the `NON_DOC` exclusion regex in the `changes` job of `.github/workflows/ci.yml`) skip `ci:local` and list `ci:local — docs only` under `## Not Run`. The patrol then has a GPT-6.1-Sol session consolidate the fork's and reviewer's candidate lessons (single writer). Role models and quota fallback: `docs/parallel-workflow.md` **Models and quota**. |
| Offline consolidation (Dreaming) & pre-release retro | Audit recent `main` commits **and** recent session transcripts against `LESSONS.md` (both pitfalls and verified recipes; unverified hypotheses are barred). Verify that paths, selectors, and links in `LESSONS.md` and `docs/subsystems/*.md` still match `main` and prune stale entries or hand-copied file lists. When an entry reaches `Seen 3×` across **3 distinct calendar dates**, promote subsystem-scoped rules into the owning `docs/subsystems/*.md` (`Critical Invariants`) and cross-cutting rules into `docs/code-standards.md`, then delete it from `LESSONS.md`. |
| Cutting a release | Read `docs/RELEASE.md`. The target commit on `main` **must** be an ancestor of `origin/main` with `ci/local-distributed == "success"` (via `npm run ci:local` or `--publish` on an identical `HEAD^{tree}` squash commit) or a `completed` + `success` manual `CI` workflow run; cancelled or incomplete runs never qualify. |
| Architecture & protocol overview | Read `docs/ARCHITECTURE.md` and `docs/SECURITY.md`. |
