# 手机端设计规范与页面层级

Bridge 手机端按“日常工作、电脑管理、App 偏好”组织为三个一级页：**会话、电脑、设置**，启动后默认进入会话。一级页之间通过顶栏左上角的菜单切换，不占用底部空间。新增或修改手机端界面时先对照下面的规范；样式变量在 `apps/client/src/mobile.css`，颜色一律取 `styles.css` 的主题变量，保证 Sunstone 与 Apple 两套风格、浅色与深色都能用。

## 设计规范

### 尺寸

| 用途 | 变量 | 值 |
| --- | --- | --- |
| 页面左右边距 | `--m-gutter` | 16px |
| 一级页大标题 | `--m-fs-large-title` | 26px |
| 二级页标题、面板标题 | `--m-fs-title` | 17px |
| 正文、操作名称 | `--m-fs-body` | 15px |
| 次要正文 | `--m-fs-callout` | 14px |
| 分组标题 | `--m-fs-subhead` | 13px |
| 说明、状态 | `--m-fs-footnote` | 12px |
| 状态标签 | `--m-fs-caption` | 11px |
| 最小点击区域 | `--m-touch` | 44px |
| 列表与操作行 | `--m-row` | 56px |
| 按钮、输入框圆角 | `--m-r-control` | 10px |
| 分组卡片圆角 | `--m-r-group` | 14px |
| 底部面板圆角 | `--m-r-sheet` | 20px |

输入框高 48px、字号 16px，避免系统自动放大页面。

### 顶栏

所有页面使用 `MobilePageHeader`：

- **一级页**（电脑、设置）：最左侧为菜单按钮，随后是大标题，下方可带一行副标题；右侧最多两个图标按钮，顺序为“+”、“⋯”。
- **会话目录**：结构同一级页，但不显示“会话”大标题，由当前电脑标签占据标题位置；标题仅保留给屏幕阅读器。
- **菜单**：点左上角菜单按钮，在按钮下方展开会话、电脑、设置三项，当前页高亮并打勾；点选项切换，点空白处或系统返回收起。
- **二级页**（对话、电脑详情、项目或归档列表）：左侧返回箭头，17px 标题和一行状态；右侧最多一个“⋯”。

### 交互约定

- **点行进入**：点会话进入对话，点电脑进入这台电脑的会话。
- **“+” 新建**：只放在一级页顶栏。
- **“⋯” 放对象操作**：会话行、对话页顶栏、电脑行。同一对象的“⋯”在不同位置打开同一个面板。
- **每个操作只有一个位置**，见下方“操作位置”。

### 弹层

| 弹层 | 用途 |
| --- | --- |
| 底部面板 `MobileSheet` | 对象操作、表单（新建会话）、审批与提问。宽度 ≥640px 时居中显示 |
| 确认框 `ConfirmationDialog` | 只用于删除、移除、退出桌面应用等破坏性操作的二次确认 |
| 弹出菜单 | 只用于一级页切换菜单和输入区的附件菜单，紧贴触发按钮 |

会话设置、切换执行来源和交给其他桌面应用沿用各自的表单弹窗；手机上使用与底部面板相同的底色和圆角。

### 操作行

底部面板里的操作用 `SheetAction`：图标、名称、一行说明。

- 按用途分成若干组（`.m-group`），每组是一张圆角卡片，行间用细线分隔。
- 破坏性操作放在最后一组，名称和图标标红。
- 当前不可用的操作保留在原位，并在说明中写明原因，例如“任务或接力进行中，先停止再删除”。
- 处理中时禁用全部操作，在面板底部显示“正在处理…”；失败原因同样显示在底部。

### 设置页卡片

- 分组标题放在卡片上方，说明文字放在卡片下方；卡片里的文字行与控件行共用相同边距。
- 电脑默认授权只有多个应用时才显示应用切换，按钮等宽；保存按钮占满卡片内容宽度。
- 桌面应用的状态文字和启动／退出按钮分成两行，避免窄屏挤压说明。
- 中继地址使用 48px 输入框和全宽保存按钮；这些布局仅应用在手机端。

### 状态点

| 状态 | 颜色 |
| --- | --- |
| 在线 | 主色实心 |
| 运行中 | 主色加外环 |
| 排队、等待处理、需重配 | 暖色 |
| 失败 | 危险色 |
| 空闲、离线 | 浅灰 |

会话行、对话页副标题、顶栏电脑标签和电脑列表使用同一套颜色。

## 操作位置

| 操作 | 位置 |
| --- | --- |
| 切换会话、电脑、设置 | 一级页顶栏左上角菜单 |
| 新建会话 | 会话页顶栏“+” |
| 同步当前电脑、展开或折叠全部项目 | 会话页顶栏“⋯”（目录选项） |
| 切换电脑 | 会话页副标题中的电脑标签 → 电脑列表 |
| 查看已归档会话 | 会话目录底部 |
| 模型、思考强度等会话设置 | 会话“⋯” → 模型与会话设置；对话页标题下方的模型行打开同一面板 |
| 查看成果、分支与主会话 | 对话页顶栏“⋯” |
| 同步此会话、Fork、切换执行来源、交给其他桌面应用、归档或恢复、删除 | 会话“⋯” |
| 停止运行中的任务 | 运行时发送键变为停止键，点击后二次确认；输入内容时恢复为发送键。Claude Desktop 运行的会话只能结束其 Claude 进程，确认框会说明影响 |
| 停止后台子代理 | 对话中子代理卡片上的“停止”；10 分钟无进展时卡片会提示可能已卡住 |
| 添加电脑 | 电脑页顶栏“+” |
| 连接、桌面应用控制、电脑默认授权 | 电脑行“⋯” → 连接与电脑设置 |
| 移除电脑 | 电脑行“⋯”；电脑详情页底部也保留同一操作 |
| 外观、Agent 显示、诊断日志 | 设置页 |

移除电脑是唯一在两处出现的操作：电脑行“⋯”是离线电脑唯一能操作的位置，详情页则以它结束这台电脑的设置。两处使用同一个确认框。

## 会话

已配对用户启动后进入最近电脑的会话目录；首次使用进入配对引导。目录只读取项目和会话清单，主动选择会话后才加载历史。

```text
会话目录
├─ 顶栏：新建（+）、目录选项（⋯）
├─ 当前电脑 → 电脑列表
├─ 搜索项目或会话
├─ 桌面应用筛选（多应用时显示）
├─ 待处理 → 对应会话的审批或提问
├─ 项目
│  ├─ 主会话（行“⋯”打开会话操作）
│  │  └─ Fork 分支 → 更深分支
│  └─ 查看全部 → 项目完整列表
└─ 已归档会话 → 搜索、查看、恢复、删除
```

项目保持原位展开。Fork 按直接父子关系逐级展开和收起；返回目录保留搜索、展开状态和滚动位置。

## 单个会话

打开会话后顶栏左侧变为返回按钮；需要切换到电脑或设置时先返回会话目录，再打开菜单。

| 位置 | 内容 |
| --- | --- |
| 顶栏 | 返回、标题、状态与模型、会话操作（⋯） |
| 内容切换 | 对话 / 成果，分支切换 |
| 对话内容 | 消息、工具、子代理报告、分支与接力链接 |
| 成果 | 文件变化、每轮成果、预览与下载 |
| 输入区上方 | 模型标签、运行中任务的停止标签、发送方式（排队或立即调整） |
| 输入区 | 图片附件、文本、发送 |

审批和提问以底部面板弹出（标题“需要处理”），提供拒绝、允许一次、始终允许或选项回答。

会话操作面板只显示主机和桌面应用支持的功能，分三组：

1. **设置与同步**：模型与会话设置、同步此会话。
2. **分支与接力**：Fork 分支、切换执行来源、交给其他桌面应用。接力沿用原有预览和确认步骤。
3. **管理**：归档或恢复；删除放在最后，需要确认，运行中或接力中的会话不能删除。

会话设置里的授权只影响当前会话，可选择跟随电脑、标准授权或完全授权。完全授权保留确认；打开设置不会改变权限。

Fork 使用当前选中父链的完整轮次边界；正在进行的输入和半轮回答不进入新分支。继承的 Agent 记录只作历史展示，不授予子分支停止父任务的权限，也不因这些历史记录阻塞交还 Desktop。子分支自己启动的后台任务仍按实际状态处理。分支共享工作目录，创建分支不会回滚文件。

### 会话命令菜单

在输入框开头输入 `/`，可查看当前会话的常用命令与自定义命令；继续输入按命令名或别名筛选。手机和 Bridge 桌面端使用同一菜单，显示说明、参数和不可用原因。支持点击、上下键、Enter／Tab 选择；选中只填入草稿，保留参数和后文，点击发送才执行。Esc、点外或手机返回键关闭菜单并保留草稿。命令不携带附件，也不作为“立即调整”插入当前轮次。

- `/help` 查看当前目录；`/context`、`/usage`、`/compact [说明]` 执行当前 SDK 提供的实际命令，结果作为系统消息保留在历史中。压缩以实际 boundary 为完成依据。
- `/model [模型]` 打开模型选择或设置支持的模型；运行中的修改从下一轮生效。`/permissions` 打开当前会话的实际权限模式及 allow／ask／deny 覆盖，显式保存后调用 SDK。规则只作用于当前 SDK 会话，不写入个人／项目设置；此处与 Bridge 电脑默认授权、原生收件箱接收许可分别显示。
- `/clear`（`/new`）进入新的空上下文，旧历史保留供 `/resume` 恢复；原会话中已排队的消息仍归原会话。`/fork [名称]` 创建并进入分支，`/resume [会话]` 选择并加载已有历史，`/rename [名称]` 将名称持久写入实际 SDK 会话记录后同步 Bridge 标题。无参数时打开相应选择或编辑面板。

已连接的 SDK 会话以初始化目录及 `commands_changed` 为准；打开菜单不会启动进程或模型。SDK 空闲释放后，显式执行命令可以重新连接。未初始化时继续读取已允许的个人 Claude `commands`／`skills` 和当前 `cwd/.claude/commands`／`skills` 元数据，隐藏 `user-invocable: false`，不向客户端传输文件正文。独立由 Claude Desktop 执行的会话不自动透传尚未验证的内置命令、不自动接管；相关项显示不可用原因。外部运行时和旧主机保留原输入行为。

### 手机交接与 Desktop 原会话的消息接收

- 支持 `session.remote-execution.v1` 的电脑端会在手机首次发送前提供“由 Bridge 继续执行”确认。取消保留草稿、图片与文件；确认选择随原指令保存到待发队列，不先投递 Desktop 收件箱。等待当前主轮、未回答的提问、子代理和后台任务结束后，才结束所选会话的闲置执行器并恢复历史继续执行。随后手机消息直接由 Bridge 执行，工具审批沿用所选设置。
- 交接等待期间显示“等待交接给 Bridge”。取消指定指令会撤销该指令的交接依据，其他未授权指令不能代替它触发交接。交接失败保留原队列并显示错误，需明确重试；不会连续发送退出信号。空闲释放、重连和重启仍保留未执行指令；主动交还 Desktop 后再次切换需要重新确认。
- 同会话已有离线旧消息需先同步。已经提交到 Desktop 的消息保持原接收状态，不自动转发到 Bridge；确认过期的原消息可按原命令编号确认接续，不创建重复指令。新功能请求在本次连接确认电脑端能力后才重放，旧宿主上保留待发输入并提示更新。
- 以下为旧客户端及仍走原生收件箱的消息接收状态：

- “已送达电脑”“已提交 Desktop”和“会话已接收”是不同阶段；只有原生记录确认消息 UUID 后才显示会话已接收。
- 原生收件箱暂挂输入时，消息显示“等待电脑允许接收”，并提示到电脑端确认。接收许可与工具执行授权独立，即使此 Desktop 会话已确认完全授权，也不能代替收件箱接收确认；等待期间无需重复发送。
- 原生接收确认过期后，原消息保留在电脑队列，显示“Desktop 接收确认已过期”，转为等待确认交接。Broker 重启后继续保留，原命令不会再次投递到同一收件箱。
- 用户可通过“接管此会话”及其确认框继续处理队列。接管仍检查主任务、子代理和后台任务，且只影响所选会话；不会自动接管。
- 原生明确拒绝、禁收、丢弃和结果不确定分别保留原有含义，不把它们当成可自动重试的确认超时。

## 电脑

电脑列表标记当前电脑。点电脑进入它的会话；不是当前电脑时先切换。“查看待处理”直接打开需要处理的会话。需要重新配对的电脑点击后进入扫码流程。

电脑行“⋯”提供：

- **连接与电脑设置**：打开电脑详情；不是当前电脑时先切换。需要重新配对的电脑显示“重新扫码配对”。
- **移除这台电脑**：需要确认。

电脑详情包含：

1. **连接与同步**：电脑在线状态、连接状态与方式、延迟、待发送数、电脑端版本、重新连接、同步、连接诊断。
2. **桌面应用控制**：应用状态、启动与退出；退出需要确认。
3. **电脑默认授权**：按桌面应用分别设置。Claude 默认授权可独立设置；其他应用通过已有会话读取配置，没有有效会话时说明限制。
4. **移除电脑**：清除该电脑在手机上的配对和缓存，并按已有机制撤销访问；需要确认。

切换一级页与查看当前电脑详情不会断开连接。主动切换电脑、重连和移除继续使用原有连接流程。

## 设置

- **外观**：显示模式（浅色、深色）和风格（Sunstone、Apple）；保留已有偏好。
- **Agent 显示**：选择哪些桌面应用出现在会话、新建和电脑控制中；Claude 始终显示。
- **诊断与支持**：记录、查看、复制或导出诊断日志，连接探测和高级排错。

电脑详情和设置共用已有诊断工具。清理缓存并重连位于高级排错区，说明影响手机上全部已保存电脑的缓存，并需要手动确认。

## 返回规则

Android 系统返回与页面返回按当前层级工作：

- 先关闭当前菜单、确认框或底部面板，再返回下层页面。
- 成果先返回对话；对话再返回原目录或项目列表。
- 项目或归档列表返回会话目录。
- 电脑详情返回电脑列表；电脑、设置一级页返回会话目录。从菜单选择“会话”也显式打开目录。
- 会话目录根页再次系统返回，应用退到后台；软键盘显示时，先由系统收起键盘。
- 返回和切页不发送或丢弃未发送草稿，也不停止电脑上的任务。

首次配对、扫码与同步保持独立流程；同步完成前不切换页面。桌面端继续使用原有导航和完整配置入口。
