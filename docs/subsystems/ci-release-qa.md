# Subsystem: CI, Release & Packaged QA

## Owned Paths
- `.github/workflows/` (`ci.yml`, `release.yml`, `release-assets.yml`)
- `scripts/` (including `scripts/fixtures/`)

## Responsibilities
- Runs full multi-platform verification locally via `npm run ci:local` (`scripts/local-ci.mjs` + `scripts/win-local-ci.ps1`): Mac M4 (`test:infra`, `audit:runtime`, `verify`, `test:browser`, `test:desktop:service`) in parallel with `ssh win` (one of 4 slots via `scp` git bundle: Windows tests + NSIS installer + packaged QA + Android SDK 36 APK/DEX/cert + WHPX headless emulator WebView E2EE pairing smoke + WSL2 `Ubuntu-24.04` Linux `test:infra`, `npm test`, and `.deb`/`.rpm`/`.zip`). Writes `<git-common-dir>/local-ci/` receipts after cleanup succeeds and publishes `ci/local-distributed = success` to `Lycidas97/claude-desktop-bridge` (`npm run ci:local -- --publish` publishes deferred or tree-identical squash-merged commits). Never attach `self-hosted` GitHub Actions runners to the public repository.
- Retains `.github/workflows/ci.yml` as a manual `workflow_dispatch` fallback running the full 7-job hosted matrix (`changes`, `verify`, `desktop-windows`, `desktop-linux`, `android-debug`, `macos-unit`, `browser-e2e`) gated by `Quality gate`. Routine PRs and `main` pushes do not spin up hosted runners.
- Orchestrates immutable single-revision draft creation and multi-platform release publishing across `.github/workflows/release.yml` and `.github/workflows/release-assets.yml`.
- Enforces Trash-only file removal in Node processes (`recycle-cleanup.cjs`) and isolates all automated QA from real user profiles, production relays, and live Claude Desktop sessions.

## Critical Invariants
1. **Manual fallback CI & zero routine hosted churn**: `ci.yml` triggers only on `workflow_dispatch` (requiring all 7 matrix jobs to succeed in `Quality gate`, with `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`). Full clean `local-ci.mjs` runs never publish `ci/local-distributed` when `--skip-*` or `--allow-dirty` is set, never publish before `finally` cleanup succeeds, and refuse `czhmartinez/*` targets.
2. **Ancestry + exact-SHA Release CI gate**: Both `release.yml` (`Require verified CI for release revision`) and `release-assets.yml` (`Resolve source and require successful CI before publication`) declare `statuses: read`, verify `git merge-base --is-ancestor "$REV" refs/remotes/origin/main`, and require either latest combined status `ci/local-distributed == "success"` on `.sha == $rev` (`commits/$REV/status?per_page=100`) or a `completed` + `success` `ci.yml` run (`push` or `workflow_dispatch`) on `main` for `.headSha == $rev`. Never reference unexported shell variables via `jq 'env.VAR'`, and never accept `in_progress`, `cancelled`, `pull_request`, or mismatched-SHA runs.
3. **Synchronized manifests & pinned Android debug key**: Root `package.json`, all workspaces, `package-lock.json`, and Android `versionName` must match exactly. Android debug builds must match SHA-256 certificate digest `8b4e8a0ed8e506dde6ff65f92b9bd526d2fcaf10d35089d381a02d9ed23a18db`.
4. **Windows QA isolation & hosted runner retention**: `windows-packaged-qa.ps1` must explicitly set both `BRIDGE_RELAY_URL` and `BRIDGE_PUBLIC_RELAY_URL` to the local test relay (empty env vars on Windows may drop and fall back to production defaults) and isolate `USERPROFILE`/`APPDATA`/`LOCALAPPDATA`. On local/developer Windows hosts (`RUNNER_ENVIRONMENT != "github-hosted"`), never execute the production-`appId` NSIS installer or uninstaller (`uninstallOldVersion` kills live host `Bridge.exe` and wipes `D:\Tools\Bridge`); stage `win-unpacked` into `$installRoot` instead and terminate only `$installRoot`-prefixed processes before Recycle Bin cleanup. On GitHub-hosted Windows Server runners (`RUNNER_ENVIRONMENT=github-hosted`), run the full NSIS install/uninstall cycle, retain packaged QA directories instead of invoking unavailable Recycle Bin directory moves, and skip NTFS junction Recycle Bin subtrees (`DE_ACCESSDENIEDSRC`).
5. **Windows CI slot isolation**: `win-local-ci.ps1` runs up to 4 concurrent `ci:local` legs, one per `Local\ClaudeDesktopBridgeWinCi-<n>` mutex (`n = 0..3`; `WaitOne(0)` sweep, then `WaitHandle.WaitAny`, with `AbandonedMutexException.MutexIndex` as the claimed slot). Everything a run writes must be keyed by the slot: worktree `D:\work\ci-slot-<n>`, anchor ref `refs/ci/slot-<n>`, AVD `bridge-ci-api36-<n>` (cloned from `bridge-ci-api36`'s `config.ini` on first use) on `-port 5560+2n` with `ANDROID_SERIAL=emulator-<port>` so every `adb` call in `windows-packaged-qa.ps1` targets its own emulator, and WSL2 `/var/tmp/bridge-linux-ci-slot-<n>`. Packaged QA ports come from `Get-FreeLoopbackPort`. On local hosts with caller-owned `BRIDGE_RECYCLE_STAGING`, install/profile roots are GUID-named directly beneath that staging directory and its owner handles final recycling; standalone runs without staging and hosted runs use `$env:TEMP`. Start the shared adb server via `Invoke-CimMethod Win32_Process Create`: Windows OpenSSH kills a session's whole process tree on disconnect, so an adb server forked inside one slot's session would die with that slot and drop the other slots' devices and forwards. Node removals during a run rename into a fresh `D:\work\cache\recycle-staging-<n>-<guid>` (`BRIDGE_RECYCLE_STAGING`), so reusing a slot does not mix new files with retained evidence from an earlier failed cleanup. The run's outer `finally` recycles that directory as one item, and a native recycle failure still fails the run: `SHFileOperation` serializes Recycle Bin moves system-wide (~0.3 s each, 30 s with a 65k-item bin), so per-test moves from 4 slots stall Vitest hooks past their 10 s timeout.
6. **Fixture honesty**: Synthetic fixtures (`native-approval-host.ts`, `browser-e2e.mjs`) prove Bridge wiring and UI state transitions; never claim they prove live Claude Desktop, macOS TCC, or physical mobile behavior.
