What it does

Your Claude work, on your phone.

Bridge forwards native Claude Desktop sessions through an encrypted connection.

One session surface

Send, stream, approve, answer questions and stop native Claude sessions from desktop or mobile.

End-to-end encryption

Per-device AES-256-GCM keys, WebRTC direct connections, and an encrypted WSS relay that never sees message content.

Native queues and forks

Queue the next instruction, withdraw eligible queued messages, or create a fork through Desktop.

Claude Desktop integration

A local Node inspector forwards explicit LocalSessions calls. Desktop owns sessions, execution and permissions.

Real evidence

View image attachments, file-change summaries and artifact previews, and download workspace files.

Built to recover

Event replay, message receipts, push wake, reconnect, session archive and delete.

Architecture

Phone, desktop host, and relay.

Devices prefer a direct WebRTC data channel. When they cannot connect directly, traffic falls back to a self-hostable relay that stores only ciphertext and routing metadata.

Read the full architecture document for native calls, events and transport.

Security

Safe boundaries are a product feature.

Bridge deliberately refuses the shortcuts that make agent remotes risky.

Explicit debugger setup On macOS, Accessibility and Automation access can open the native debugger menu once per Desktop process.
Local inspector only The local Node inspector forwards explicit native operations. Relay requests cannot evaluate arbitrary code.
No OAuth extraction Account credentials remain in Claude Desktop.
No hidden chain-of-thought Only bounded, user-visible context travels between devices.
No automatic failover Unavailable Claude sessions remain unavailable; Bridge does not start another executor.
No credential migration Desktop account credentials are not copied to the phone or relay.

Full details in the security model.
